**Stato:** piano **eseguito** (risultati e lacune dichiarate: [consegna finale](m3-final-delivery.md) §5 e §7). _Testo alla progettazione:_ proposta, nessun test scritto · **Baseline:** `5a0d056eda`.
Indice: [tasks-index.md](tasks-index.md). Convenzioni e strumenti: quelle esistenti (Vitest nei 4 pacchetti, API su D1 reale con `m3-helpers`, RTL, Playwright E2E e **preview con CSP reale**, `db:check`, `db:upgrade-test`).

**Regola di processo (dalla lezione della CI 42334739111):** ogni E2E che cambia scheda o apre un dialog attende lo **stato ARIA** (`openTab`, `toBeVisible` del pannello), mai il solo URL; i `describe` seriali non dipendono da dati lasciati da altri test; ogni test di tempo/race è provato **con CPU limitata** (throttling CDP ≥ 6×) prima di essere accettato.

## 1. Dominio (`packages/shared`, puro, senza I/O)

| Area                    | Casi obbligatori                                                                                                                                                                                                                                                                                                              |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `localDate`             | **mezzanotte**: `23:59:59.999` e `00:00:00.000` locali in `Europe/Rome`, `America/New_York`, `Asia/Kolkata` (+5:30), `Pacific/Kiritimati` (+14), `Pacific/Pago_Pago` (−11); **DST**: 2026-03-29 (Roma, salta 02→03) e 2026-10-25 (ripete 02→02); `UTC`; fuso non valido → errore; istante a cavallo di fine anno; 29 febbraio |

| `summarizeTasks`        | zero task; tutte aperte; mix di stati; **oracolo** per i test SQL                                                                                                                                                                                                                                                             |
| Stati e transizioni     | tabella completa 3×3 comando/stato (idempotenza, rifiuti)                                                                                                                                                                                                                                                                     |
| Priorità                | ordine `urgent > high > medium > low > none`, coerente con le card                                                                                                                                                                                                                                                            |
| Follow-up               | `kind` non cambia stato né ordine; **suggerimenti S1/S2/S3**: ogni regola compare/non compare (task in ogni stato, anchor, card chiusa/archiviata), una sola per volta con priorità, determinismo con `today` fisso, ignorati                                                                                                 |

## 3. API

| Area                | Casi                                                                                                                                                                                                        |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CRUD                | crea (card-less e con card), legge, modifica ogni campo, ricollega/scollega; risposte sempre passate da `Schema.parse`                                                                                      |
| Stati e transizioni | matrice §1 «Stati»: 9 combinazioni comando × stato; timestamp invariati sui replay; `updated_at` monotono (due scritture nello stesso ms)                                                                   |
| Autorizzazione      | non autenticato 401; workspace altrui 404; task altrui 404 **identico** a inesistente; `viewer` 403 sulle scritture; il test di **enumerazione delle rotte** include `/tasks*`                              |
| Isolamento          | `cardId` di altro workspace → 404; task con id di altro workspace → 404; nessun elenco/contatore include righe altrui (due workspace popolati)                                                              |
| Concorrenza         | due `PATCH` con lo stesso `expectedUpdatedAt`: uno 200, l'altro 409; `complete` ‖ `cancel`; creazione concorrente allo stesso tetto                                                                         |
| Idempotenza         | matrice di [contratti §4](tasks-api-contracts.md): replay 200, payload diverso 409, simultanei identici/diversi, replay dopo modifica (stato corrente), errore forzato a metà → nessuna riga parziale       |
| Paginazione         | cursore stabile con `dueOn` uguali, con inserimenti/completamenti **fra** una pagina e l'altra (nessun duplicato né salto), cursore manomesso → 400, `limit` 0/101 → 400, ultima pagina `nextCursor = null` |
| Filtri e ordine     | ogni `view`; `cardId` (incluse archiviate); esclusione delle archiviate senza `cardId`; ordine totale con parità di data/priorità/creazione                                                                 |
| Archiviazione card  | archivia → task invariate ma escluse dall'elenco e dai contatori; scritture 409; **ripristina** → riappaiono identiche                                                                                      |
| Pipeline            | chiudere/riaprire una candidatura **non** modifica le task; completare una task **non** modifica la pipeline (confronto prima/dopo)                                                                         |
| Limiti di input     | titolo 200/201, descrizione 2.000/2.001, data valida/impossibile, chiavi sconosciute, corpo > limite                                                                                                        |
| Riservatezza        | nessun titolo/descrizione nei log (test come quello esistente di logging); nessun campo non dichiarato in uscita                                                                                            |

| Area                          | Casi                                                                                                                                                                                                       |

## 7. Quality gate per checkpoint

Ogni checkpoint chiude con: `typecheck`, `lint`, `format:check`, `check:contrast`, `check:config`, `check:brand`, `test:identity`, `db:check`, `db:upgrade-test`, `pnpm test`, `pnpm build`, `pnpm test:e2e`, `pnpm test:preview` **e** la CI remota del commit (se il push è autorizzato). Si dichiara verde **solo** ciò che è stato eseguito, con i conteggi. Nessun test disabilitato o trasformato in `skip`; nessun aumento di timeout come correzione.
